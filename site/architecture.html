Architecture

Four lanes, two gates, one audit trail.

Traffic is served by exactly one champion at a time. Everything else — monitoring, retraining, shadow scoring, gating — exists to decide, with evidence, when that champion should change.

1

Serve

the only lane that touches users
Input
Live requests
Loan applications scored one at a time.
→
API
FastAPI /predict
API-key auth · returns risk score + probability · 2.1 ms median latency.
→
Model
Champion
The one model in Production stage. Nothing serves traffic but this.
⇄
Registry
MLflow
59 tracked runs, versioned artifacts, one Production stage at a time.
2

Monitor

runs on every incoming batch
Input
Incoming batches
Recent traffic, sampled from the live stream.
→
Detector
PSI + KS per feature
Laplace-smoothed PSI > 0.2, KS p < 0.01 — each feature compared against frozen training-set bins.
→
Vote
≥ 3 of 19 features flagged?
One noisy feature is expected. Three agreeing is drift.

Clean → no action, result still audit-logged.  ·  Drifted → lane 3 fires.

3

Challenge

triggered by drift, never by a schedule
Trigger
Retrain challenger
Fresh labeled data folded into the training set; logged as a new MLflow run.
→
Shadow
Shadow scoring
The challenger scores the same traffic as the champion — logged, never served.
→
Gate 1 · Performance
ΔAUC ≥ +1.0 pp
Must beat the champion by a full point of AUC on recent labeled data.
→
Gate 2 · Fairness
FPR disparity ≤ 5 pp
False-positive rates compared across age bands. Bias blocks promotion.
4

Decide & record

three outcomes, all logged
✓ Promoted

Passed both gates. Registered as a new champion version in MLflow and serving cuts over to it.

− Rejected

Insufficient AUC gain. In simulation, 18 of 18 weak challengers were correctly turned away.

✕ Blocked

Better AUC, worse bias. One challenger at +7.65% AUC was blocked for a 22.4 pp subgroup disparity.

●

Audit trail. Every decision — drift cause, champion-vs-challenger metrics, fairness result, timestamp, final outcome — is appended to a structured JSONL log. 23 entries and counting. If a regulator asks why a model was promoted, the answer is one line of JSON away.
